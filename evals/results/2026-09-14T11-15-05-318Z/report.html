## 补丁

```rust
// src/interp.rs

// 栈空按 0 算。想让下溢重新变响，只改这一处：.expect("stack underflow")
fn pop(stack: &mut Vec<u64>) -> u64 {
    stack.pop().unwrap_or(0)
}

pub fn run(code: &[u8]) -> Vec<u64> {
    let mut stack: Vec<u64> = Vec::new();
    let mut pc: usize = 0;

    while pc < code.len() {
        let op = code[pc];
        match op {
            0x00 => break,   // STOP
            0x01 => {        // ADD
                let a = pop(&mut stack);
                let b = pop(&mut stack);
                stack.push(a.wrapping_add(b));
                pc += 1;
            }
            0x02 => {        // MUL
                let a = pop(&mut stack);
                let b = pop(&mut stack);
                stack.push(a.wrapping_mul(b));
                pc += 1;
            }
            0x03 => {        // SUB — a 是栈顶，结果 a - b
                let a = pop(&mut stack);
                let b = pop(&mut stack);
                stack.push(a.wrapping_sub(b));
                pc += 1;
            }
            0x04 => {        // DIV — 除零得 0，不是 panic
                let a = pop(&mut stack);
                let b = pop(&mut stack);
                stack.push(if b == 0 { 0 } else { a / b });
                pc += 1;
            }
            0x05 => {        // SDIV — 有符号；除零得 0；MIN / -1 回绕成 MIN
                let a = pop(&mut stack) as i64;
                let b = pop(&mut stack) as i64;
                stack.push(if b == 0 { 0 } else { a.wrapping_div(b) as u64 });
                pc += 1;
            }
            0x06 => {        // MOD — 模零得 0
                let a = pop(&mut stack);
                let b = pop(&mut stack);
                stack.push(if b == 0 { 0 } else { a % b });
                pc += 1;
            }
            0x50 => {        // POP
                pop(&mut stack);
                pc += 1;
            }
            0x60..=0x7f => { // PUSH1 ..= PUSH32
                let n = (op - 0x60) as usize + 1;   // <-- 关键修复：PUSH1 读 1 字节
                let mut v: u64 = 0;
                for i in 0..n {
                    v = (v << 8) | code[pc + 1 + i] as u64;
                }
                stack.push(v);
                pc += 1 + n;
            }
            _ => panic!("unknown opcode {:#x} at pc {}", op, pc),
        }
    }
    stack
}
```

DIV/SDIV/MOD 的除零返回 0 是 EVM 的规定行为（不是异常），SUB 的操作数顺序是栈顶减次栈顶——这两点跟 MHOT 对齐时最容易出分歧，专门标出来。

`unwrap_or(0)` 按你要求加了，但提醒一句：PUSH 修好之后 add_ones 那个「下溢」就不存在了，它现在挡的是真下溢。**差分对照里静默补 0 比 panic 危险**——MHOT 遇到下溢会报错，你这边返回个数值，跑出来的 diff 要么是假阳性、要么把 MHOT 的真 bug 盖掉。所以我把它收进了一个 `pop()` 函数，你想翻回 panic 就改那一行。

## 证据

`let n = (op - 0x60) as usize;` — PUSH1 (0x60) 算出 `n = 0`，即读 0 个立即数字节、`pc += 1`。也就是说 PUSH1 压了个 0 上去，然后 pc 落在了操作数那个字节上。三条 trace 全部由此精确推出：

**add_simple** `[0x60, 05, 0x60, 03, 0x01, 0x00]`
pc=0 走 PUSH1，n=0，压 0，pc=1 → pc=1 读到 `0x05` → `_` 分支 panic。报的就是 `unknown opcode 0x5 at pc 1`。

这里的 `0x05` **不是 SDIV 指令，是 "PUSH1 5" 里的那个字面量 5**（你自己的注释写了）。解释器因为没跳过立即数，把数据当成了操作码。`_ => panic!` 这个分支没坏，它恰恰在正确报告"pc 落到了非指令边界上"。把 SDIV 补进 match 不是修好，是把这个报警关掉 —— 之后它会把操作数当指令静默执行下去。

**add_ones** `[0x60, 01, 0x60, 01, 0x01, 0x00]`
pc=0 压 0，pc=1 读到 `0x01` 当 ADD → pop 出那个 0，第二次 pop 空栈炸。panic 在 `12:37`，正是 `let b` 那一行 —— 说明栈上恰好只有一个值，跟"压了个幻影 0、第二个 PUSH1 根本没执行到"完全吻合。字节码本身是配平的，栈不是真的下溢。

**push2** `[0x61, 0x2a, 0x00]`
n = 0x61-0x60 = 1，只读了一个字节 → 42，第二个立即数 `0x00` 被当成 STOP 吃掉了。`left: [42]` 就是这么来的。这条其实是三个里最干净的一条：没有 panic、没有缺指令，只是结果正好少了一个字节 —— 它单独就能定位这个 bug，不是"另一个毛病"。

你昨晚核 `0x60..=0x7f` 那一步没问题，这个范围本身是对的，PUSH1..PUSH32 就是它。错的是下面一行的"操作码 → 立即数宽度"换算。我知道你说了别看 PUSH，但三条 trace 都指到这儿，绕不开。

## 关于 `unwrap_or(0)`

建议今晚别加，理由跟你的用途直接相关：这两个 panic 是被上面的 bug 逼出来的，本身不是真下溢。而一旦真下溢了，`unwrap_or(0)` 会把"崩"变成"算出一个错的数"。差分对照的全部价值在于参照实现要吵 —— MHOT 那边跑出个错值，你这边静默返回 0，差异会被归到 MHOT 头上。真 EVM 遇到栈下溢是异常halt。要处理的话正确形状是 `run` 返回 `Result<Vec<u64>, EvmError>`，让 harness 能把"两边都 revert"判成一致，但那是改签名的活，不是今晚的事。

**`add_simple` `[60 05 60 03 01 00]`**

- pc=1，code[1]=`0x05` → 落 `_` → `unknown opcode 0x5 at pc 1`

**`add_ones` `[60 01 60 01 01 00]`**

**`push2` `[61 2a 00]`**
- n = 0x61-0x60 = 1 → 只读了 1 个字节 `0x2a` = 42 → `[42]`

要读 2 个字节才是 `0x2a00`。
